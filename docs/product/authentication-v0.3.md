# FlowTrace 身份接入需求 v0.3

本阶段把 FlowTrace 从可信网络中的匿名工具演进为可以识别操作者的多用户系统。
本文覆盖并替代 v0.2 文档中“暂不提供登录认证”的范围判断，不改变既有领域模型
和过程记录规则。

## 决策

- 认证是必需能力，不提供匿名或可关闭模式；
- 每个部署只启用一种登录适配器，首批支持本地账号、标准 OIDC 与企业微信；
- Better Auth 承担会话、外部账号和个人 API Key，不自行实现通用认证框架；
- 登录账号与 Person 分离；账号解决“谁能登录”，Person 表示可被排期的参与者；
- 外部登录首次出现时，以可信邮箱关联预建 Person；未命中时自动创建 Person，
  未取得可信邮箱时拒绝建档；
- 人员关联不得按姓名猜测，也不允许普通用户从目录中自行认领身份；
- 姓名和邮箱的管理权由适配器声明；来自企业目录的字段在 FlowTrace 中只读；
- 本地模式首次打开时创建唯一所有者，完成初始化后永久关闭自主注册；
- 管理者仍可创建不会登录的虚拟成员、外部协作者或待入职成员；
- Web、HTTP API 和 MCP 使用同一身份边界；
- MCP 密钥属于个人，可撤销，系统必须知道每次调用代表谁；
- 当前阶段不引入 RBAC，登录用户拥有实例内相同的业务能力；
- 全局机器人和代用户执行属于后续阶段，不得伪装成个人 API Key。

## 验收

1. 未登录浏览器只能进入登录页，匿名 HTTP API 与 MCP 请求返回未认证；
2. 部署必须明确选择且只选择一个登录适配器，配置不完整时拒绝启动；
3. 本地模式只在空实例显示所有者初始化，之后登录页不再出现注册入口；
4. 外部身份按已验证邮箱关联现有 Person，未命中时自动创建；提供方未返回可信
   邮箱时阻止首次建档，不按姓名猜测；
5. 已被其他账号占用的邮箱或稳定身份产生冲突时阻止登录并提示管理员处理；
6. 企业目录管理的姓名和邮箱不可在人员目录或个人资料中修改；
7. 未关联登录账号的 Person 可以正常参与排期，并可在未来首次登录时自动关联；
8. 用户可以创建和撤销个人 MCP 密钥，完整密钥只显示一次；
9. MCP 使用个人密钥访问，并且内部转调 HTTP API 时不丢失调用身份；
10. 缺少认证密钥或登录适配器时应用拒绝启动，而不是退回匿名模式。
