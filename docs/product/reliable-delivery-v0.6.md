# 可信记录与交付协作 v0.6

本增量统一交付范围、历史语义和 Agent 协作规则，并在人员工作台与版本视图中
提供可处理、可追溯的关注事项。

## 交付与历史

- Version 承担当前归属需求，以及目标修复版本指向它的 Bug。Bug 未单独指定
  目标版本时使用父需求版本；不能重复计入两个交付。
- 已取消 Bug 不属于开放缺陷。汇总数字必须与同范围的明细一致。
- 版本变化事件保存发生时的范围与对象名称；迁移事件同时属于迁出和迁入版本。
  后续改名、迁移或删除不得改写过去事件的上下文。
- 旧数据无法恢复发生时名称时，明确标记为重建上下文，不伪称精确历史。
- 已发布版本必须具有实际发布日期。发布本身不表示所有工作已完成，遗留事项
  必须仍可查看，并在交付说明中记录决策和去向。
- 移除版本要求没有当前归属需求或目标修复 Bug。检查和移除必须与迁入操作
  互斥，不能留下引用已隐藏版本的工作。

## Agent 与日常录入

- 确定事实、缺失信息和 Agent 建议应分开。只有已获授权的事实更新进入正式数据。
- 简单录入沿用现有单项工具。已有流程的取消、接替或依赖替换使用完整预演。
  当用户已经明确确认了同一份具体变更内容时，无须重复确认；新增业务选择或
  影响范围变化时，展示新差异后再确认。该规则覆盖 v0.4 的重复确认要求。
- 预演只能承载服务声明支持的操作。不支持原子录入的复杂来源必须明确边界，
  不得伪装成一个原子事务。
- 服务提供当前调用者身份、能力版本和可完整翻页的变化查询。
- 写入应具有稳定执行标识；相同身份以同一标识重放同一操作返回原结果，参数
  改变则拒绝。超时后可查询结果，避免盲目创建重复对象。
- 业务审计区分实际发起人、调用方式和 Agent 自报模型。身份由认证上下文提供，
  不接受 Agent 自行指定实际操作者。
- 来源标识用于关联会议、消息或资料片段，可以跨多个变更复用；它与请求幂等键
  含义不同。来源只保留必要链接与摘要，不建立聊天全文存储平台。

## 交付检查与关注事项

- 版本检查同时呈现未完成需求、开放修复、等待、阻塞、外部依赖和需要补全的
  信息，所有条目可跳转到原业务对象。
- 人员关注队列优先呈现预计恢复已过、计划已过期、阻塞和需要本人处理的事项。
  需求协调职责与阶段、Bug、待办执行职责保持区分。
- 提醒依据结构化事实生成；事实更新后自动消失。没有安排不得解释为人员空闲。
- 交付复盘基于可追溯的历史事实；并行阶段的累计时长不得当作人员工时或需求
  的自然持续时间，Agent 不得仅凭相关性断言延期原因。

## 接入边界

外部 Agent 宿主（包括 Multica）负责会话、用户交互、凭据传递和确认状态；
FlowTrace 负责业务规则、稳定身份映射、数据与审计。宿主通过公开 HTTP/MCP
接口接入，不直接依赖领域服务或数据库表。已有读写接口保持兼容，新能力通过
服务能力清单发现。
