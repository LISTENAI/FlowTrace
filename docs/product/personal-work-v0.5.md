# 人员工作与零碎待办增量需求 v0.5

本文定义以人为中心的跨项目工作视图，以及不能自然归入需求或项目的零碎
待办。它覆盖早期需求中暂缓“个人工作台”的范围判断，不改变既有项目、版本、
需求、阶段和 Bug 的含义。

## 产品目标

- 登录后可以直接看到“我”在多个项目中负责的阶段、Bug 和零碎待办。
- 所有人都可以切换查看其他人员的已记录安排；当前版本不引入管理者角色。
- 以时间线表达计划和实际过程，但没有已记录安排不得被解释为人员空闲。
- 项目时间线直接显示每项需求、阶段和 Bug 当前记录的负责人。

## 人员视角

人员时间线汇总阶段、Bug 和零碎待办。需求负责人表示整体协调职责，不应把
整个需求工期算作这个人的执行占用，因此在独立区域列出。

当前版本所有已认证用户共享相同的读取和维护能力。未来引入项目可见性或权限
策略时，人员视角必须复用同一可见性过滤，不能绕过项目权限。

## 零碎待办

零碎待办是一级业务对象，用于尚不能归入具体需求、甚至不能归入项目的独立
工作。它具有稳定的 `TODO-N` 编号、标题、说明、负责人、状态、三层时间及其
历史。项目和需求关联都是可选的；关联需求时，项目必须由该需求确定。

不得为了收纳待办创建“杂项项目”或伪造需求。待办不参与需求完成度计算，也
暂不参与依赖关系。创建人用于追溯来源，不等同于负责人。

## 交互要求

- “我的工作”是主导航入口，并可搜索切换人员。
- 新增待办默认分配给当前查看的人，但允许调整负责人。
- 人员时间线内可以记录状态、调整计划、分配负责人和打开原业务对象。
- 项目时间线的负责人采用紧凑展示，不以增加常驻按钮挤压任务名称。
- 无计划的事项仍然可记录状态和实际过程，并明确显示为“未排期”。
