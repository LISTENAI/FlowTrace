# v0.6 实施与接入交底

本轮完成可信记录、Agent 调用策略和交付工作台三个功能单元。产品边界见
`docs/product/reliable-delivery-v0.6.md`；原始产品档案保留，按增量文档覆盖。

## 已落地

- 版本需求与目标修复 Bug 的范围统一，取消 Bug 不算开放；完整性提示与外部
  依赖同样携带实际版本范围。事件保存发生时名称与迁入/迁出上下文，旧记录
  明确标为 reconstructed。空版本删除和迁入使用数据库锁；发布必须有实际日期。
- 项目与人员聚合批量读取关联历史，人员查询先按负责人筛选。变化查询支持
  固定时间上界和游标；搜索提供范围、分页与总数；来源标识可反查相关事件。
- 写入回执和业务修改同事务提交，支持按认证用户隔离的幂等重放。审计区分
  实际操作者与 Agent 自报模型；补录返回本次新增历史。旧 HTTP 响应保持兼容。
- Skill 0.6.0 修正待办路由、重复授权、原子能力边界和失败恢复，复杂方法按需
  加载。服务提供推荐版本与内容摘要；实际宿主的已安装 Skill 仍需单独更新。
- 版本交付检查提供六类可跳转事项与交付说明。人员关注队列区分执行和协调，
  按恢复逾期、阻塞、计划逾期与待确认事实排列；事实变化后重新计算。
- 页面按路由加载，主入口 JS 从约 575 KB 降到约 219 KB（未压缩构建产物）。

## Multica 和其他宿主

继续使用公开 HTTP/MCP。`get_capabilities`、`get_current_identity`、
`get_operation_result` 和 `get_version_delivery_check` 是新增工具；既有工具不
改变名称和主要响应结构。`get_changes_since`/`search` 在 `data` 数组之外增加
`pagination`；写工具增加 `mutation`。实际 Schema 以 `tools/list` 为准。

宿主保存具体授权内容、每次执行的原参数与 request_id。超时不自动更换执行
标识；先查结果或原样重放。共享机器人凭据的 actor 只代表机器人账号，不能
冒充消息发送人的真实认证身份。FlowTrace 本轮没有引入委托身份协议。

镜像升级后核对能力、提交修订和 Skill 摘要。生产部署由部署任务完成，本轮
本地提交不等于已上线，也不自动更新 Multica 或其他宿主里的 Skill。

## 验证范围

- 后端 69 项测试在独立 PostgreSQL 16 上通过，包括真实并发重放、删除/迁入
  互斥、迁移、事务回滚、跨版本交付和历史补录。内存套件跳过两项真实锁用例。
- MCP 三项测试覆盖工具协议与传输恢复；HTTP 端到端套件调用真实 MCP→API。
- typecheck、build、format:check 通过；Skill 官方格式校验通过。
- 本地浏览器检查交付页、个人队列和接入页，覆盖明暗主题、390px 窄屏与桌面，
  验证原事项跳转、版本信息、编辑入口。没有运行生产数据写入或部署验收。
- `evals/flowtrace` 的 18 个场景与判分材料已就绪；实际模型的 MCP-only 与
  MCP+Skill 对照尚未运行，不能把协议回归当作模型行为已通过。

## 后续边界

完整原子导入（创建需求、Bug、迁移版本和待办）、待办升级、结构化交接产物和
基于历史的复盘页继续作为后续增量。先用真实使用数据衡量录入耗时、重复率、
人工修正次数和关注项处理率，再决定是否扩展。当前交付检查不自动授予“验收
通过”，交付说明也尚未成为独立的结构化验收对象。

查询游标不跨请求持有数据库快照，持续同步需要重叠窗口并按事件 ID 去重。
回执当前保留原结果，不自动清理；未来清理需保留幂等墓碑。搜索仍在内存排名。
领域服务进一步拆分及长期查询预算、真实模型评测和 Web 自动交互回归可继续
补充；本轮仅将关注规则和写入事务上下文先拆出。pg 驱动在事务内并行排队查询
会输出未来大版本弃用提示，升级 pg 前应改为顺序查询或独立连接。
